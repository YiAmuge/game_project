# 도시 경계 1.1 온라인 대전

참가자는 웹 링크를 열기만 하면 됩니다. 앱 설치·계정 가입·포트 개방은 필요하지 않습니다. 방장이 브라우저에서 경기를 계산하고, 참가자는 자신의 조작만 보냅니다. 최대 8명이 4 대 4로 참가하며 빈자리는 방장이 AI 챔피언·무작위 AI·없음으로 설정합니다.

## 플레이

1. 메인 메뉴의 **방 만들기 / 방 참여**를 누르고 닉네임을 입력합니다.
2. 방을 만든 뒤 **초대 링크 복사**로 링크를 공유합니다. 방 코드를 직접 입력해도 됩니다.
3. 빈 슬롯의 **이 자리로**를 눌러 팀과 포지션을 정하고 챔피언을 선택합니다.
4. 참가자들이 **준비**를 누르면 방장이 **경기 시작**을 누릅니다.
5. 경기 종료 후 방장이 **대기실로 돌아가기**를 누르면 다시 편성할 수 있습니다.

대기실 하단에서 채팅할 수 있습니다. 챔피언은 중앙 목록에서 선택하고 추천 표시와 역할군 필터를 사용할 수 있습니다. 방장은 빈 슬롯의 **챔피언 선택**으로 AI도 편성합니다.


PC·모바일이 같은 방에 참가할 수 있습니다. 설정창·도감·모바일 세로 전환은 온라인 경기를 일시정지하지 않습니다. 화면이 가려지면 자신의 이동·공격 입력은 해제됩니다. 방장 브라우저는 전면에서 실행해 주세요. 모바일의 화면 잠금·앱 전환으로 방장 브라우저가 정지하면 경기도 진행되지 않을 수 있습니다.

참가자가 연결을 잃으면 캐릭터를 AI가 맡습니다. 같은 브라우저에서 45초 안에 새로고침하거나 연결을 복구하면 기존 캐릭터로 돌아옵니다. 방장이 나가거나 방장 연결이 끊어지면 방과 경기가 종료됩니다. 방장 이관과 중도 신규 참가는 지원하지 않습니다.

## 공개 링크 배포 — 운영자 1회 설정

이 저장소는 공개 URL을 자동 발급하거나 유료 서비스를 신청하지 않습니다. 아래 배포를 한 번 완료하면 플레이어는 발급된 HTTPS 링크로 접속합니다. 정적 파일만 제공하는 GitHub Pages에서는 방 연결 서비스를 실행할 수 없습니다.

가장 간단한 배포는 [Render Blueprint](https://render.com/deploy?repo=https://github.com/YiAmuge/game_project&branch=codex/city-border-v0.2)입니다. Render에 로그인해 이 저장소의 `render.yaml`을 적용하면 Node 웹 서비스가 게임 페이지와 방 연결을 함께 제공합니다. 저장소 접근 권한이 필요할 수 있습니다. 무료 서비스는 유휴 상태에서 잠들 수 있어 첫 접속이 늦을 수 있습니다. 서비스의 현재 요금·전송량 한도는 배포 전에 확인하세요.

다른 호스팅에서도 Node 22 이상과 WebSocket 업그레이드를 지원하면 실행할 수 있습니다.

```sh
npm ci
npm run online
```

운영자 로컬 테스트는 `http://localhost:5173`입니다. `PORT` 환경변수로 포트를 바꿀 수 있습니다. 인터넷에서는 호스팅 서비스의 HTTPS 주소를 공유하고, 프록시가 `/online` WebSocket을 전달하도록 설정합니다. Docker 배포도 지원합니다. 외부 공개 주소가 없는 `localhost` 링크는 다른 사람의 기기에서 방장에게 연결되는 주소가 아닙니다.

`npm start`·`npm run dev`로 사용하는 기존 개발 서버도 방 서비스를 제공합니다. 내려받은 단일 HTML의 AI 대전·연습장은 계속 오프라인에서 동작하지만, 그 파일에는 방 서비스가 없어 온라인에는 배포된 웹 링크가 필요합니다.

## 연결 구조

- WebSocket은 방 생성·참가·편성·준비·채팅과 WebRTC 연결 정보를 관리합니다.
- 기본 전투 통신은 방장과 각 참가자 사이의 WebRTC DataChannel입니다.
- 직접 연결이 4초 안에 열리지 않거나 끊기면 같은 서비스의 WebSocket 중계로 자동 전환합니다. 중계는 패킷 전달만 하며 전투를 계산하거나 저장하지 않습니다. 따라서 모바일 통신망에서도 추가 설정 없이 사용할 수 있습니다.
- 방장은 초당 30회 시뮬레이션하며 변경된 개체 상태를 최대 초당 15회 전송합니다. 참가자는 별도 AI·피해 판정을 실행하지 않습니다. 명령은 보낸 참가자의 캐릭터에만 적용합니다. 시야·상점·스킬 재사용 대기·탄창·충전 규칙은 방장 게임에서 검사합니다.
- 신뢰할 수 있는 순서 보장 통신, 청크 분할, 전송 대기량 제한을 적용합니다. 중계 사용량은 운영자의 호스팅 전송량에 포함됩니다. 현재 버전은 참가자가 방장을 신뢰하는 사용자 방입니다.

선택적으로 TURN을 설정하면 직접 연결이 불가능한 환경에서도 게임 서비스 대신 TURN으로 DataChannel을 중계할 수 있습니다.

```text
TURN_URLS=turn:your-relay.example:3478,turns:your-relay.example:5349
TURN_USERNAME=issued-user
TURN_CREDENTIAL=issued-credential
```

coturn의 공유 비밀 방식이면 `TURN_USERNAME`·`TURN_CREDENTIAL` 대신 `TURN_SECRET`을 사용합니다. 서버가 유효기간이 있는 자격증명을 발급합니다. 실제 비밀 값을 저장소에 커밋하지 마세요. TURN을 설정하지 않아도 WebSocket 자동 중계는 동작합니다.

## 검증

```sh
node --test tests/online.test.js tests/server.test.js tests/v73.test.js
MOBA_TEST_URL=http://127.0.0.1:5173 python tests/online_browser.py
```

방장과 참가자는 반드시 같은 버전이어야 합니다. 서버 재배포·재시작 시 메모리에 있는 방은 종료됩니다.

## 채팅과 현황

인게임 채팅은 같은 방의 전체 참가자에게 전달됩니다. PC는 Enter로 열고 Enter로 보내며 Esc 또는 빈 Enter로 닫습니다. 모바일은 상점 아래 채팅창을 누르고, 닫기 또는 뒤로가기로 닫습니다. 채팅 중에도 경기는 진행됩니다. 작성자 접두사는 팀 색으로 표시하고 핑은 기존처럼 아군에게만 보입니다. 메시지는200자까지이며 연속 전송 간격은0.6초입니다. 채팅 내역은 방 서버 메모리에 최근60개만 보관되며 방 종료 시 사라집니다.

점수창에는8명의 초상화·닉네임·레벨·KDA·강화 단계·증강이 함께 표시됩니다. PC에서는 점수창을 열어 둔 채 WASD로 이동할 수 있습니다.
